# SubAgent 系统 Spec

## 背景

ch15 之后 MewCode 有 Hook 系统（子 Agent 动作占位待对接），但主 Agent 只有一个对话上下文：长任务里探索、审查、实现混在一个历史里，上下文互相污染；工具结果堆积逼近窗口上限；权限询问、token 计数无从分离。ch13 的独立技能模式已证明「独立会话 + 独立 Agent + 摘要回流」可行，但它绑定技能场景、无后台任务概念。

本步把委派能力泛化：主 Agent 用统一 Agent 工具把子任务委派给独立的子 Agent——每个子 Agent 有自己干净的上下文、受限的工具集、独立的权限追踪；定义式按预定义角色执行，Fork 式继承父对话历史并借 prompt cache 降成本；子 Agent 跑完结果异步通知回主对话，上下文污染彻底解决。

## 目标

- 一个统一的 `agent` 工具，`type` 参数分流「定义式」和「Fork 式」两条路径，工具列表始终稳定
- 角色用 Markdown + YAML frontmatter 定义，四级目录加载、同名高优先级覆盖
- 定义式空白对话+固定角色；Fork 式全量继承父对话历史与工具集，首请求命中缓存
- 运行时状态隔离（消息、权限、文件读缓存、token 计数），基础设施共享（LLM 客户端、Hook 引擎、文件系统）
- 子 Agent「跑到底」非交互执行，模型不再调工具即完成，结果注入主历史并自动续轮
- 工具过滤三层防线：全局禁止再委派、角色白/黑名单、后台剔除再委派工具——防无限嵌套
- 后台任务管理器：状态/结果/用量追踪，三种进入后台方式（显式指定、60s 超时自动、/tasks 手动切），Fork 强制后台

## 功能需求

### F1: 角色定义与四级加载

- 角色文件 = Markdown + YAML frontmatter：`name`（必填，唯一名）、`description`（必填，一句话）、`tools`（可选，工具白名单）、`deny_tools`（可选，工具黑名单）、`model`（可选）、`max_rounds`（可选，最大轮次，缺省=主 Agent 上限 30）、`permission`（可选 strict/default/accept，缺省=inherit 父当前档位）；未知字段忽略（向前兼容）；字段类型非法=解析失败跳过并警告
- 正文是子 Agent 的系统提示（身份、职责、工作风格），伴随整个生命周期
- 四级目录（优先级从高到低）：项目 `<根>/.mewcode/agents/` > 用户 `~/.mewcode/agents/` > 内置 `mewcode/agents/`（随包分发，含 general 等样板）> 插件 `~/.mewcode/plugins/*/agents/`；同名高优先级静默覆盖；解析失败跳过并警告，不阻断
- 格式沿用 skills 的 `*.md` / `*/AGENT.md` 双形态

### F2: 统一 agent 工具

- 工具名 `agent`，参数：`type`（defined|fork，必填）、`role`（角色名，defined 必填）、`prompt`（任务描述，必填）、`background`（可选布尔，fork 强制 true 忽略显式 false）
- 非法 type / 角色不存在 / prompt 缺失 → 工具返回失败结果（含合法取值提示），模型可纠正；工具列表始终只含这一个 agent 工具名

### F3: 定义式启动

- 空白 ChatSession + 角色正文作为系统提示的自定义指令块（替换主对话的 custom_instructions，其余 stable 模块共享）；环境补充块与记忆索引共享
- 工具集 = 角色白名单（非空时）再应用三层防线；`agent` 工具绝不出现

### F4: Fork 式启动

- 对话历史 = 父对话全部消息（含工具调用与结果）+ fork 任务 user 消息；系统提示 stable 前缀与父一致——首请求消息序列与父完全相同，prompt cache 最大化命中
- 工具集 = 父当前可见工具（再应用全局禁止：剔除 agent）
- Fork 强制走后台（同步等待无意义——父上下文就是起点，主对话不能空等）

### F5: 运行时状态隔离与基础设施共享

- **隔离**：消息（独立 ChatSession）、权限（独立 PermissionGate：新 RuleSet、角色档位、父会话规则不传入）、文件读缓存（新建：read_file 按路径+mtime 键控缓存，命中不重读磁盘，缓存归属 Agent 实例互不可见）、token 计数（独立统计，回报任务管理器）
- **共享**：LLM 客户端（同 provider 或角色 model 重建）、HookManager（同一实例）、工具注册表、文件系统、存盘目录（独立子目录防序号撞车，ch13 同款）

### F6: 跑到底模式

- 非交互执行：不发出权限询问事件，闸门 ASK 一律自动拒绝并回灌「非交互模式无法人工确认，已拒绝」，模型改用只读工具或规则内工具
- 停止条件 = 模型不再调工具（正常完成）或达 max_rounds 上限或异常；完成结果 = 最终助手回复

### F7: 工具过滤三层防线

- ① 全局禁止：`agent` 工具不进任何子 Agent 的工具集
- ② 角色限制：`tools` 白名单（非空时只给这些工具）；`deny_tools` 黑名单（再从结果集中剔除）；Fork 无角色，继承父可见工具
- ③ 后台白名单：进入后台的任务，工具集再剔除 `agent`/`use_skill` 等再委派工具（即使②含它们）——后台任务不能启动新子 Agent

### F8: 后台任务管理器

- 任务状态追踪：`running`/`done`/`failed`，附角色名、耗时、token 用量、结果摘要
- 三种进入后台方式：显式 `background=true`；同步子 Agent 运行超 60 秒自动转后台（主对话立即继续）；`/tasks detach <id>` 手动把进行中的同步任务切后台
- `/tasks` 命令列出全部任务（状态、耗时、用量）；Fork 恒后台

### F9: 结果通知与自动续轮

- 子 Agent 完成（done）：最终回复作为一条 user 消息注入主对话历史（含角色名与任务标识）；失败（failed）：失败说明同样注入
- 注入发生在主对话空闲时（主对话运行中则等其本轮结束，ch13 轮末 drain 同款）；注入后自动触发主对话一轮，让主 Agent 汇报或继续

### F10: Hook 共享与 subagent 动作对接

- 子 Agent 共享主对话的 HookManager：内部工具调用照常触发 tool_before/tool_after 等事件，拦截语义与主对话一致
- 对接 ch15 遗留：hook 的 `subagent` 动作从占位改为真实启动——动作扩展可选 `role` 字段（缺省内置 general 角色），启动定义式子 Agent（后台），动作返回成功；ch15 的 loader 校验相应扩展

## 非功能需求

- **N1**：主对话不被拖慢——同步子 Agent 有 60 秒上限自动转后台；后台任务绝不阻塞主循环与输入
- **N2**：缓存友好——Fork 首请求的消息序列与父完全一致（不重排不裁剪），系统提示 stable 前缀逐字节不变
- **N3**：失败隔离——子 Agent 异常/失败绝不中断主对话；结果照常注入，主循环照常
- **N4**：可观测——任务状态随时可查（`/tasks`），完成通知出现在对话里，触发/完成有日志
- **N5**：资源上限——同时运行的后台任务数上限（5 个），超出时 agent 工具返回失败原因，防后台任务爆炸
- **N6**：兼容——无角色目录或模型不调 agent 工具时，行为与 ch15 完全一致；ch15 存量测试不破

## 不做的事

- Worktree 文件隔离（子 Agent 与主对话共享文件系统，不建独立工作树）
- 多 Agent 团队编排（子 Agent 之间不直接通信，只与主 Agent 交互）
- 后台任务跨会话持久化（进程退出任务即终止，不落盘恢复）
- 后台任务的取消/暂停控制（本步只有启动、查询、切后台）
- 角色定义的热重载（启动时加载一次）
- 插件系统的实现（插件层目录约定先立，插件加载机制本身不做）

## 验收标准

- **AC1（F1）**：四级目录各放一个同名角色（不同正文），加载结果取项目级版本；缺 `name`、非法 `permission` 值的角色文件被跳过并警告、其余角色照常加载
- **AC2（F2）**：`agent` 工具非法 type 返回失败且信息含合法取值；`role` 不存在返回失败且信息含可用角色名；无论何种调用工具列表始终只有一个 `agent` 工具名
- **AC3（F3）**：定义式启动——子 Agent 对话从空白开始（无父消息）、系统提示含角色正文、工具集=角色白名单再应用防线（断言无 `agent` 工具）
- **AC4（F4）**：Fork 启动——子对话=父全部消息+任务消息；首请求消息序列与父一致、系统提示 stable 相同（缓存命中）；`background: false` 的 fork 调用仍进入后台
- **AC5（F5）**：父 Agent 读某文件后子 Agent 再读同文件不命中父缓存（各自独立缓存实例）；父会话 grant 的权限规则不影响子 Agent 裁决；子 Agent 的 token 用量与父独立统计并回报任务管理器
- **AC6（F6）**：子 Agent 遇 ASK 自动拒绝、回灌「非交互模式无法人工确认」原因，模型改用只读工具继续完成任务（跑到底）
- **AC7（F7）**：任何子 Agent 的可见工具集不含 `agent`；角色 `deny_tools` 从白名单中剔除生效；后台任务的工具集不含 `agent`/`use_skill`
- **AC8（F8）**：`/tasks` 列出全部任务及状态/耗时/用量；三种进入后台方式各验证一次（显式、60s 超时自动转、`/tasks detach`）；同时运行后台任务达 5 个后再启动返回失败原因
- **AC9（F9）**：子 Agent 完成后结果作为 user 消息注入主历史（含角色名与任务标识），主对话空闲时自动续一轮并汇报
- **AC10（F10）**：hook `subagent` 动作真实启动定义式子 Agent（未写 role 用内置 general）；子 Agent 内部工具调用照常触发 tool_before Hook 且拦截生效
