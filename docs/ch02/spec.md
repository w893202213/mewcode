# Ctrl+C 双击退出 Spec

## 背景

MewCode TUI 当前在输入行阶段按 Ctrl+C 只是放弃当前输入行继续运行，退出只能靠 `/exit` 命令或 Ctrl+D（EOF）。流式回复期间按 Ctrl+C 会直接抛出 KeyboardInterrupt traceback 崩溃。参考 Claude Code 的交互习惯，本步实现「按两次 Ctrl+C 退出」，并顺带让流式期间的 Ctrl+C 变成「中断回复」而非崩溃。

## 目标

- 输入行阶段：第一次 Ctrl+C 只提示、不清行；3 秒内第二次 Ctrl+C 退出程序回到 CLI
- 流式回复期间：Ctrl+C 中断本次回复、回到输入行，程序不退出、不崩溃
- 不改变 `/exit` 与 Ctrl+D 的现有退出行为

## 功能需求

- F1: 输入行阶段按一次 Ctrl+C：保留当前已输入内容，并显示提示「再按一次 Ctrl+C 退出」
- F2: 提示显示后的 3 秒窗口内再按一次 Ctrl+C：程序正常退出（退出码 0）回到 CLI；窗口超时则计数重置、提示消失，下次 Ctrl+C 重新开始计数
- F3: 流式回复进行中按 Ctrl+C：立即中断本次回复渲染，回到输入行；程序不退出、不输出 traceback；流式期间的 Ctrl+C 不参与双击计数，中断后双击计数从头开始
- F4: 中断回复后，本轮未完成的用户消息与部分回复不留在会话上下文里（与现有请求失败的回滚行为一致）
- F5: `/exit` 与 Ctrl+D 的退出行为保持不变

## 非功能需求

- N1: 不引入新的第三方依赖，基于 prompt_toolkit 现有机制实现
- N2: 双击窗口判定不受系统时间调整影响
- N3: 提示语使用中文，与现有 TUI 文案风格一致

## 不做的事

- 时间窗口固定 3 秒，不做配置项
- 不改变启动/配置加载阶段的 Ctrl+C 行为（进入 TUI 主循环后才生效）
- 不做其他按键组合的退出方式（如按三次、Esc 退出等）
- 不保证中断后服务器端生成真正停止（中断以中止流式渲染为准）

## 验收标准

- AC1: 输入行输入内容后按一次 Ctrl+C → 输入内容保留，显示「再按一次 Ctrl+C 退出」提示（对应 F1）
- AC2: 提示后 3 秒内再按一次 Ctrl+C → 程序退出回到 shell，退出码 0（对应 F2）
- AC3: 提示后等待超过 3 秒再按 Ctrl+C → 程序不退出，重新显示提示、重新计数（对应 F2）
- AC4: 流式回复进行中按 Ctrl+C → 回复停止渲染，回到输入行，无 traceback，程序继续运行（对应 F3）
- AC5: 流式中断回到输入行后按一次 Ctrl+C → 只提示、不退出（证明计数已重置）（对应 F3）
- AC6: `/exit` 与 Ctrl+D 均可退出，行为与改动前一致（对应 F5）
