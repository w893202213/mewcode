# Hook 系统 Spec

## 背景

ch14 之后 MewCode 已有完整的 Agent 循环（会话→轮次→消息→工具四层）、权限闸门（工具执行前裁决，拒绝原因回灌给模型）、YAML 集中校验配置。但重复性自动化动作仍靠人工盯：比如「每次 run_command 前检查参数」「每轮开始提醒某约束」「会话结束清理临时文件」这类触发条件明确、动作固定的工作无法固化，每次都要用户手动介入。

权限闸门已证明「工具执行前拦截 + 拒绝原因作为工具结果回灌」模式可行。本章把这种能力泛化：在 Agent 生命周期的关键节点上挂自动化动作，让机器在合适的时刻自动做该做的事。

## 目标

- 用「事件 + 条件 + 动作」三要素声明式描述规则，条件可省略，YAML 集中加载并逐条校验
- 事件覆盖四层生命周期（会话/轮次/消息/工具）加系统级，共 10 个事件
- 工具执行前事件可拦截：拒绝原因作为工具结果反馈给模型，让它自行调整
- 条件匹配支持精确、反向、正则、glob 四种语法；多条件用「全部满足」或「任一满足」组合
- 四种动作：shell 命令、注入提示词、HTTP 请求、子 Agent（占位）
- Hook 自身失败只记日志，绝不中断 Agent 主流程

## 功能需求

### F1: 规则三要素结构

- 配置文件顶层 `hooks:` 列表声明规则，每条规则由 `event`（必填）、`if`（可省略，省略=无条件触发）、`action`（必填）三要素构成
- 单条 `if` 直接写条件映射；组合条件写 `all:`（全部满足）或 `any:`（任一满足）键，二者互斥

### F2: 10 个事件及触发时机

- **会话级**：`session_start`（会话创建/恢复后）、`session_end`（会话结束）
- **轮次级**：`round_start`（一轮用户输入开始）、`round_end`（一轮结束，上下文含结束原因）
- **消息级**：`user_message`（用户消息落盘后）、`assistant_message`（助手消息落盘后）
- **工具级**：`tool_before`（预检全部通过后、实际执行前，可拦截）、`tool_after`（执行完成后，上下文含工具结果）
- **系统级**：`startup`（程序启动）、`shutdown`（程序退出）
- 独立技能运行路径（ch13）同样触发会话/轮次/消息/工具级事件

### F3: 条件匹配

- 四种模式语法（单串判定）：`!` 前缀→反向（剩余部分匹配后取反）；`/.../` 包裹→正则；含 `*`/`?`→glob（沿用现有 `**/` 归一）；其余→精确相等
- 条件字段：每个事件定义固定顶层字段（`event`、`round`、`tool` 等）；工具级事件支持 `args.<参数名>` 点路径嵌套访问
- 字段不存在时该条件不命中
- `all`/`any` 组合二选一，不混用、不嵌套

### F4: tool_before 拦截

- Hook 在权限闸门放行之后、执行之前触发——是闸门的补充，不绕过既有安全体系
- 拒绝语义：命令动作按退出码（非 0→拒绝，stdout 为拒绝原因）；HTTP 动作按状态码（非 2xx→拒绝，响应体截断为原因）；注入提示词/子 Agent 动作无拒绝通道，执行即放行
- 被拒绝的工具调用不执行，拒绝原因作为工具失败结果回灌给模型（复用现有失败结果通道），模型可据此调整
- 拦截动作自身失败（超时/无法执行）：fail-closed——拒绝该调用，原因=失败信息，同时记日志

### F5: 四种动作

- **command**：执行 shell 命令；环境变量暴露 `MEW_EVENT` 及事件相关常用字段（工具级含 `MEW_TOOL`、轮次内含 `MEW_ROUND`），完整事件上下文 JSON 经 stdin 传入
- **inject**：注入提示词——静态文本拼进下一次 LLM 请求的系统提示词补充块，请求发出后即移除（一次性消费）
- **http**：发 HTTP 请求（url/method/headers/body 字段），有超时；非 2xx 记日志，响应不回灌模型
- **subagent**：启动子 Agent（占位，只校验格式，不真实运行）

### F6: 执行控制

- `run_once`：该规则本次进程运行期间只执行一次，之后跳过（不持久化，进程内标记）
- `background`：动作后台异步执行不阻塞事件流；`tool_before` 禁止 `background`（拦截必须同步拿结果）
- `timeout`：命令/HTTP 动作超时上限（秒），超时按失败处理；仅 command/http 生效

### F7: 失败隔离

- 动作执行失败（命令非零退出、HTTP 异常、超时等）只写日志，绝不中断 Agent 主流程
- 拦截类事件上动作失败按 F4 的 fail-closed 处理（拒绝调用，同样是日志+回灌，不中断）

### F8: 加载与集中校验

- 启动时从 config.yaml 顶层 `hooks:` 加载全部规则，逐条校验，任一非法即报错（中文、fail-closed 口径与现有配置一致）
- 校验内容：event 合法、field 合法、pattern 为正则时编译成功、action 类型与字段齐全、tool_before 与 background 冲突、timeout 为正数
- 规则为空/无 hooks 字段时静默跳过（无 Hook 运行）

## 非功能需求

- **N1**：未配置 hooks 时零开销——主循环行为与 ch14 完全一致，无 Hook 管理器时不做任何额外工作
- **N2**：同步动作必须受超时约束——单条 Hook 无论怎样都不能无限挂起主流程（命令/HTTP 缺省超时 30 秒）
- **N3**：可观测——每条 Hook 的触发、条件不命中跳过、动作失败均有日志，含事件名与规则序号；日志只增不减，不覆盖原有日志
- **N4**：边界清晰——Hook 拦截是权限闸门的补充而非替代：闸门先裁决（硬边界不动），Hook 在其放行路径上追加策略；计划模式过滤与技能白名单过滤均先于 Hook 生效

## 不做的事

- 子 Agent 动作的真实运行（本步只占位，等 SubAgent 章节对接）
- `run_once` 标记持久化（进程内标记，重启即重置）
- Hook 执行顺序的显式优先级（同事件多条规则按配置文件顺序执行）
- 注入提示词的模板变量替换（本步只支持静态文本）
- HTTP 响应体回灌给模型（只记日志）
- Hook 规则的运行中热重载（启动时加载一次）
- 事件上下文的修改语义（Hook 只能放行/拒绝，不能改写工具参数或消息内容）
- 多层配置（用户级/项目级）——本步单层

## 验收标准

- **AC1（F1）**：写一条只有 `event` + `action`（无 `if`）的规则，对应事件无条件触发一次（观察日志/注入效果）
- **AC2（F2）**：对 10 个事件各挂一条注入/命令规则，跑一次真实会话（含一轮工具调用），观察到全部事件按各自时机触发，且独立技能运行路径同样触发轮次/工具级事件
- **AC3（F3）**：对同一字符串分别用精确、glob、`!` 反向、`/正则/` 四种模式写条件，命中结果符合预期；`all` 两条件都真→触发、一条假→不触发；`any` 反之；`args.command` 点路径在参数缺失时条件不命中
- **AC4（F4）**：`tool_before` 挂一条按参数拒绝的命令规则（如参数含 `rm -rf` 退出 1），观察到：工具不执行、模型收到含拒绝原因的失败结果、后续能调整行为；拦截动作超时同样拒绝该调用
- **AC5（F5）**：四种动作各验证一次——command 收到 stdin 完整 JSON 且环境变量正确；inject 文本出现在下一次 LLM 请求且请求后消失；http 收到请求且非 2xx 只记日志；subagent 规则能通过加载校验（占位）
- **AC6（F6）**：`run_once` 规则在两次触发机会中只执行一次；`background` 命令执行期间事件流继续（会话不卡顿）；`tool_before` 配 `background: true` 启动报错
- **AC7（F7）**：挂一条命令退出 1 的 Hook 和一条 HTTP 超时的 Hook，主流程照常完成一轮对话，日志有失败记录
- **AC8（F8）**：非法 event、编译失败的正则、`tool_before`+`background` 冲突、非正数 timeout 分别导致启动报错（中文、指向具体规则）；hooks 字段缺失或为空时正常启动，行为与 ch14 一致
