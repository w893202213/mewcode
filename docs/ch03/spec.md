# 输入回显移除与思考期计时提示 Spec

## 背景

当前 TUI 存在两个体验问题：

1. **输入重复回显**：用户按回车提交问题后，prompt_toolkit 的输入行本已留在终端滚动区，`_chat_round` 又以 `▸ 你 <原文>` 形式打印一遍，用户的问题在屏幕上出现两次，无任何信息增量。
2. **思考期无提示**：从请求发出到首个流事件到达期间（网络往返 + 模型首 token 前处理，可能持续数秒），Live 渲染区域为空，终端没有任何提示；思考模式开启时思考块也要等首个思考增量才出现。用户无法区分「正在思考」和「卡死」。

## 目标

- 移除不必要的用户输入回显。
- 请求发出后立即显示灰色 thinking 提示，并实时显示已思考秒数；回复正文开始流式输出时停止计时并隐藏提示。

## 功能需求

- F1: 用户输入提交后，终端不再重复打印用户消息原文（prompt_toolkit 输入行保留在滚动区即可），会话记录行为不变。
- F2: 对话请求发出后，立即在助手区域显示灰色「thinking…」提示（含计时），覆盖从请求发出到首个流事件到达的静默期。
- F3: 计时器从请求发出时刻开始计时，显示经过的整秒数（如 `thinking… 3s`），每秒至少刷新一次。
- F4: 思考内容增量流式期间，计时继续显示（与思考块并存）；回复正文首个增量到达时停止计时并隐藏提示。
- F5: 计时提示不影响现有渲染与交互：思考块灰色展示、Markdown 流式渲染、ProviderError 错误提示、Ctrl+C 中断提示、双击 Ctrl+C 退出。

## 非功能需求

- N1: 计时提示使用灰色样式，与现有思考块的 dim 风格协调。
- N2: 计时基于本地单调时钟，显示粒度 1 秒。
- N3: 不引入额外线程或异步改造——利用现有 rich Live 的自动刷新机制周期性重渲染计时内容。

## 不做的事

- 不在回复末尾显示总耗时（仅思考期计时）。
- 不改动 mock 服务与 provider 协议，不新增流事件类型。
- 不做跨轮次的计时统计或历史记录。
- 不改动会话落盘逻辑（用户消息仍正常写入会话）。

## 验收标准

- AC1（F1）: 输入问题回车后，屏幕上用户问题只出现一次（即 prompt 输入行本身），不再出现 `▸ 你 <原文>`。
- AC2（F2）: 输入问题回车后，在无任何流事件到达的静默期内，终端立即显示灰色 thinking 提示。
- AC3（F3）: 提示中的秒数随时间增长，每秒至少刷新一次。
- AC4（F4）: 思考模式下，思考增量流式期间计时仍可见；回复正文首个增量到达后提示消失，正文开始流式。
- AC5（F5）: 错误（ProviderError）、Ctrl+C 中断、双击 Ctrl+C 退出等既有行为不受影响。
- AC6: 思考块与计时提示并存时不重叠、不错位、不闪烁。
