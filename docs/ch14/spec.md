# ch14 /skill 技能列表命令 Spec

## 背景

现状（ch13 后）：技能系统完成三级发现与两阶段加载——启动时把全部技能的
「名字 + 一句说明」注入模型上下文，模型按需经 use_skill 加载完整指令；
技能激活后注册斜杠短命令，进 /help 与 Tab 补全。但对**用户**来说，
没有一条命令能随时查看「当前有哪些可用技能、哪些已激活」：
/help 只显示已激活技能的短命令（ch13 AC12），看不到未激活的技能；
技能清单注入的是模型上下文，用户不可见。

## 目标

- 输入 `/skill` 即可看到全部可用技能列表：每个技能一行「名称 + 一句描述」，
  已激活的技能带激活标记，一眼看清哪些可用、哪些正在生效

## 功能需求

- F1: `/skill` 命令——输入 `/skill` 显示全部可用技能列表：按名称排序，
  每行「名称 + 一句描述」；已激活的技能行首带激活标记（★），未激活的不带。
  列表末尾附统计行（如「共 N 个技能，M 个已激活」），无激活技能时统计行省略。
- F2: 列表数据源 = 启动时三级目录扫描得到的生效技能集（覆盖/解析失败者
  不出现，会话中新增技能文件不出现——与 ch13 F4 一致）；激活状态实时反映：
  技能激活后 /skill 立即出现标记，/clear 后标记立即消失。
- F3: 无任何可用技能时显示「没有可用技能」提示文案（不显示空列表）。
- F4: `/skill` 是内置命令：出现在 /help 列表与 Tab 补全中（ch12 注册机制
  自动获得）；技能名与 `skill` 撞名的技能激活时跳过短命令注册并警告，
  内置 /skill 不受影响（复用 ch13 AC13 撞名机制）。

## 非功能需求

- N1 行为确定性：/skill 是纯本地计算——只读内存中的技能表与激活状态，
  不发起模型调用，不写磁盘。
- N2 兼容：ch12 全部命令与 ch13 技能系统行为不回退（/help、Tab 补全、
  技能短命令、/clear 联动等按原验收场景重跑）。
- N3 解耦：列表渲染是纯函数（输入技能表与激活状态，输出文本），
  不依赖渲染框架，可脱离 TUI 独立单测。

## 不做的事

- `/skill <名字>` 单个技能详情——只做列表（如需详情留到后续章节）
- 列表不显示来源层级（project/user/builtin）、执行模式、工具白名单、
  目录路径等元信息——保持一行一个技能
- 列表内交互选择/激活——/skill 只展示，激活仍走 use_skill 或短命令
- 不修改技能发现与激活逻辑——本功能纯新增展示命令

## 验收标准

- AC1（F1）：启动后输入 `/skill` → 显示全部技能，每行「名称 + 一句描述」，
  按名称排序，已激活的行首带 ★ 标记，末尾显示「共 N 个技能，M 个已激活」；
  无激活技能时统计行省略
- AC2（F2）：输入 `/skill` → 无 ★ 标记；激活某个技能后再输入 `/skill` →
  该技能行首出现 ★；`/clear` 后再输入 → ★ 消失
- AC3（F2）：会话运行中新增技能文件 → `/skill` 列表不含该技能（重启生效）
- AC4（F3）：无任何可用技能的环境下输入 `/skill` → 显示「没有可用技能」提示
- AC5（F4）：`/help` 列表包含 `/skill`；输入框 Tab 补全菜单包含 `/skill`
- AC6（F4/N2）：创建一个名为 `skill` 的技能并激活 → 短命令跳过注册并警告，
  内置 `/skill` 行为不受影响
- AC7（N2）：ch12 全部命令与 ch13 技能系统按原 checklist 重跑不回退
