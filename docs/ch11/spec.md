# ch11 记忆系统 Spec

## 背景

现状（ch10 后）：MewCode 每次启动都新建空的 ChatSession（`tui/app.py`），退出即丢弃，Agent 每次都「失忆」。唯一的长期信息是 `~/.mewcode/config.yaml` 里的 `custom_instructions` 字段——单层、无项目级、纯手写。ch09 已有上下文压缩能力（Compressor / TokenEstimator），但只在单次会话内工作。

目标：新会话启动时自动恢复项目知识和用户偏好，让 Agent 从「每次失忆」变成「越用越懂你」。靠三套机制分层管理记忆：

- **项目指令文件**：手写、静态，项目/用户两层优先级，随系统提示每轮注入
- **会话存档**：JSONL 追加写的工作记忆，中断后能平滑续接
- **自动笔记**：LLM 异步提炼的长期记忆（四分类 + 索引注入）

## 功能需求

### F1 项目指令文件三层加载

- 三层指令文件（优先级从高到低）：
  1. 项目根 `MEWCODE.md`
  2. 项目根 `.mewcode/instructions.md`
  3. 用户目录 `~/.mewcode/instructions.md`
- 拼接时高优先级排前面（模型优先遵循），全部注入系统提示的【自定义指令】块；现有 `config.yaml` 的 `custom_instructions` 字段内容作为用户级最末段保留（向后兼容）。
- 任意一层缺失：静默跳过；文件读取失败：打印中文警告，不阻断启动。
- 支持 `@include <路径>` 引用（行首指令）：
  - 相对路径相对于当前文件所在目录解析
  - 嵌套深度上限 3 层，超出截断并警告
  - visited 集合防环：同一文件只加载一次，重复引用跳过
  - 越界拦截：项目级文件的 include 目标必须在项目根内；用户级文件（`~/.mewcode/instructions.md`）的 include 目标必须在 `~/.mewcode/` 内。越界路径跳过并警告。

### F2 会话自动存档

- 每次启动自动创建一个新会话：ID 为 `YYYYMMDD-HHMMSS-xxxx`（xxxx 为 4 位随机字符，同秒撞车自动重试），存档文件为 `.mewcode/sessions/<ID>.jsonl`。
- 每行一条 JSON 记录；每轮 Agent Loop 结束后把本轮新增消息追加写盘，记录内容含：用户消息、助手消息（文本/思考/工具调用）、工具结果消息。
- 不维护独立 meta 文件：会话标题（首条用户消息截断）、消息数等需要时直接扫 JSONL 现算。
- 追加写、不整文件重写；崩溃最多只丢最后一行。

### F3 会话恢复

- 入口一：CLI 参数 `--resume [会话ID]`，缺省恢复最近一个会话。
- 入口二：TUI 命令 `/resume`，列出最近 5 个会话（标题、ID、最后活动时间），输入编号选择恢复。
- 恢复加载时的异常处理：
  1. **坏行跳过**：JSON 解析失败或关键字段缺失的行跳过；有跳过时打印「跳过 N 行无法解析的记录」。
  2. **截断**：assistant 消息带工具调用但没有配套工具结果的（崩溃未写完的尾巴），丢弃该消息及其后所有消息。
  3. **token 超限先压一次**：恢复后估算历史 token，超过窗口安全阈值（沿用 ch09 needs_auto 口径）时立即压缩一次并提示，不等首轮请求。
  4. **时间跨度提醒**：最后一条消息距今超过 7 天时，插入一条提醒消息（说明原时间点），让模型意识到上下文是历史存档。
- 恢复成功后欢迎面板显示会话 ID、标题、消息数；恢复后的新消息继续追加写原 JSONL。
- 存档文件一条有效记录都没有：报错提示，按新会话继续。

### F4 过期会话清理

- 启动时扫描 `.mewcode/sessions/`，删除 30 天以上未修改的会话文件，打印清理提示（删除数量）。

### F5 自动笔记与索引注入

- 笔记分四类：**用户偏好**、**纠正反馈**、**项目知识**、**参考资料**。
- 触发时机：一轮 Agent Loop 自然结束（模型最终回复无工具调用，即正常 OK 收尾）后，异步调用 LLM：读本轮对话 + 现有索引 + 相关笔记，判断本轮是否产生值得记录的笔记；新增/更新/丢弃与去重均由 LLM 判断。
- 存储：项目级笔记在 `.mewcode/memory/`、用户级在 `~/.mewcode/memory/`，笔记归属（用户级/项目级）也由 LLM 判断。每条笔记一个 Markdown 文件，frontmatter 含 name、description、type、更新时间。
- 索引文件：每级目录一份 `memory/index.md`，在每轮请求前随系统提示构建时读取注入（相当于 Agent 已经「读过」），本轮新产生的笔记下一轮即可见；索引控制在 200 行 / 25KB 以内，更新笔记后若超限由 LLM 顺带精简。
- 异步更新不阻塞输入与下一轮；每轮自然结束最多触发一次；更新失败静默降级（最多一条灰色提示）。

### F6 启动流程

- 启动顺序：加载三层指令 → 创建/恢复会话 → 清理过期会话 → 注入记忆索引 → 欢迎面板（含恢复信息或新会话提示）。

## 非功能需求

- N1 崩溃安全：JSONL 追加写，坏行恢复跳过。
- N2 记忆相关文件损坏不阻断启动：指令文件、索引、会话文件异常均警告后继续。
- N3 索引规模 ≤200 行且 ≤25KB。
- N4 笔记更新异步、不阻塞；每轮最多触发一次。
- N5 不引入新第三方依赖（标准库实现）。
- N6 回归：权限（ch07）、MCP（ch08）、压缩（ch09）行为不变，现有测试全部通过。

## 不做的事

- 向量数据库、RAG 检索、团队记忆同步（留给后续章节或专门项目）。
- 会话全文搜索、跨项目会话浏览。
- 手动编辑笔记的交互命令。
- 多会话并行、会话合并。

## 验收标准

- AC1（F1）: 三层指令文件各写不同内容后启动，发起请求，三份内容按「项目根 → 项目 .mewcode → 用户目录 → custom_instructions」顺序出现在系统提示的指令块中。
- AC2（F1）: `@include` 引用项目内文件正常展开；引用项目外路径被跳过且打印警告；循环 include 不死循环；嵌套超过 3 层被截断并警告。
- AC3（F2）: 跑一轮对话后正常退出，`.mewcode/sessions/` 下出现一个 JSONL 文件，每行合法 JSON，行数与对话消息数一致。
- AC4（F3）: `--resume` 恢复后对话历史完整可用（模型能看到之前内容），新消息继续追加写同一文件；`/resume` 列表中能看到该会话。
- AC5（F3）: 手工构造含「末尾半行坏数据 + 无配套结果的 tool_use 尾巴」的存档 → 恢复时坏行被跳过、截断至完整轮次，且提示信息正确。
- AC6（F3）: 恢复一个 token 超限的会话 → 启动即压缩一次并提示，不等到首轮请求。
- AC7（F3）: 恢复一个 7 天前的会话 → 注入时间跨度提醒消息。
- AC8（F4）: 手工构造 30 天前 mtime 的会话文件 → 启动后被删除且打印清理提示。
- AC9（F5）: 对话中告诉 Agent「我偏好中文回答」→ 轮结束后 `.mewcode/memory/` 出现/更新用户偏好笔记，索引文件更新且 ≤200 行 / 25KB；下一轮请求的系统提示包含该记忆索引。
- AC10（F5）: 轮结束后可立即输入下一轮（异步更新不阻塞交互）。
- AC11（N2）: 指令文件/索引文件写入损坏内容 → 启动仍成功，打印警告。
- AC12（N6 回归）: 现有全部单元测试通过；tmux e2e 主流程（提问 → 工具调用 → 回复）不受影响。
