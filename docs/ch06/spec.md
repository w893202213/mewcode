# 结构化系统提示 Spec

## 背景

MewCode 前五章做通了对话、工具系统、Agent Loop 和 Plan Mode，但有一个结构性空白：**从未给模型发过系统提示**——两家 provider 的请求体里连 `system` 字段都没有。模型唯一的「全局指引」是六个工具的描述和它自己的常识。三行全局指令（身份、擅长、先思考再行动）只存在于设想中，从未进入任何请求。

由此带来三个具体问题：

1. **行为靠运气**：「优先用专用工具」「编辑前必先读」这类约定没有成文，模型遵守率不稳定；
2. **成本线性**：多轮 Agent Loop 每轮都把会话历史原样重发，无任何缓存，token 全价计费；
3. **Plan Mode 污染历史**：ch05 因当时无 system 机制，把 Plan 指令写成 user 消息塞进会话（当时已注明是权宜之计）。

本章把三行指令展开成**结构化系统提示**：稳定指令走缓存通道省钱省时，环境信息与动态指令通过系统级补充块注入，让 MewCode 从「能干活」变成「干得好」。

## 目标

- **结构化**：七个固定模块（身份、系统约束、任务模式、动作执行、工具使用、语气风格、文本输出）按优先级拼装，后接环境信息与可选模块，方便以后插新模块
- **缓存**：稳定指令与工具描述进入可缓存前缀；动态补充不打断缓存；通过缓存命中字段验证策略真生效
- **双重强化**：关键规则同时写进全局指令与工具描述，提高「优先用专用工具」「编辑前必先读」的遵守率
- **系统级补充注入**：带特殊标签的补充块（环境信息、Plan 指令）走系统通道，不污染缓存、不被当成用户输入
- **按轮次注入**：Plan 指令首轮完整、每隔 N 轮重复完整、其余精简，控制注入频率
- **可验证**：解析 API 缓存命中字段并展示，配合典型场景人工对比做定性评估

## 功能需求

### F1: 结构化系统提示拼装

- 七个固定模块按优先级排列：**身份 → 系统约束 → 任务模式 → 动作执行 → 工具使用 → 语气风格 → 文本输出**；其后接**环境信息**，再后接可选模块（**自定义指令、已激活的 Skill、长期记忆**）
- 每个模块有简短标题标识，模块之间空行分隔，整体按优先级从前往后拼装
- 三行原文语义完整吸收进各模块：第 1 行（你是 MewCode，终端 AI 编程助手）→ 身份；第 2 行（擅长读代码、写代码、调试）→ 身份与任务模式；第 3 行（先思考再行动，解释推理过程）→ 系统约束与文本输出——且表述与 extended thinking 兼容：推理在思考区进行，正式回复给结论与关键理由、不重复整段推理
- 本章可选模块中只有**自定义指令**有数据源（config.yaml 字段）；**已激活的 Skill** 与**长期记忆**是空槽位，本章不参与拼装，但拼装框架支持未来注册
- 拼装是纯函数式过程：给定固定模块内容、环境信息、自定义指令与开关状态，产出最终系统提示文本——不依赖网络与界面

### F2: 稳定/动态分离与缓存通道

- **稳定部分**＝七个固定模块文本＋工具描述；**动态部分**＝环境信息＋会话级开关指令（Plan 指令）
- 稳定部分进入可缓存前缀：
  - Anthropic 协议：稳定系统块末尾与最后一个工具上加缓存断点（`cache_control: ephemeral`）
  - OpenAI 协议：系统消息中稳定文本排在最前（依赖服务端自动前缀缓存，如 DeepSeek），不引入协议外机制
- 动态补充永远位于缓存断点之后/稳定文本之后，不打断缓存前缀
- 多轮循环中每轮重新发送，稳定前缀保持不变（缓存命中），仅动态部分变化

### F3: 系统级补充注入

- 补充内容以**带特殊标签的形式**（如 `<supplement>` 包裹、内部按小节组织）注入**系统通道**：Anthropic 协议为 system 字段中的补充块；OpenAI 协议为系统消息尾部
- 角色上是 system 而非 user，模型不会把它当成用户输入来回复
- 补充块包含两部分：环境信息（工作目录 cwd、操作系统 platform、当前日期）＋当前生效的会话级开关指令（Plan Mode）
- 补充块**不写入会话历史**，不随历史永久累积；每轮请求动态生成

### F4: Plan 指令按轮次注入（迁移 ch05 机制）

- Plan Mode 开启期间，每轮 LLM 调用注入 Plan 指令：**首轮完整版**、**每隔 4 轮重复完整版**、**其余轮次精简版**（如仅一句「Plan Mode 开启中：仅只读工具」）
- 删除 ch05 往会话写 `PLAN_MODE_ON/OFF` user 消息的做法——注入迁移到系统通道，会话历史不再出现这两条消息
- `/plan`、`/do` 的可观测行为不变：工具收窄为只读、副作用工具不执行、切回后恢复全工具
- 注入节奏机制通用化：任何会话级开关都能声明「完整版文本＋精简版文本＋重复间隔」，当前唯一的开关是 Plan Mode

### F5: 关键规则双重强化

- 关键约定同时写进**全局指令**（工具使用/动作执行模块）与**对应工具描述**，两处互相呼应：
  - 「优先使用专用工具」：读文件用 read_file 而非 shell 里的 cat；搜代码用专用搜索工具而非 grep
  - 「编辑前必先读」：修改文件前必须先读当前内容，确保替换文本与文件一致
- 强化后的表述为中文、可执行、无歧义；改动工具描述时同步检查全局指令是否呼应

### F6: 缓存命中解析与展示

- Anthropic 协议：解析 usage 中的 `cache_creation_input_tokens`（写缓存）与 `cache_read_input_tokens`（命中读取）
- OpenAI 协议：解析 usage 中的 `prompt_cache_hit_tokens`/`prompt_cache_miss_tokens`（兼容服务返回时）
- token 用量信息扩展缓存字段；TUI 用量行展示缓存命中情况（如「缓存命中 1234 tokens」）
- 服务端不返回缓存字段时：不展示、不影响任何既有行为（优雅降级）

### F7: 配置扩展

- config.yaml 顶层新增可选字段 `custom_instructions`（多行文本），内容拼进「自定义指令」模块
- 缺省（不填）时该模块不参与拼装，系统提示不含该模块

## 非功能需求

- **N1 依赖**：不新增第三方依赖——缓存断点、标签注入均为请求体组装逻辑，标准库实现
- **N2 协议一致**：两家协议可观测行为一致（能力允许范围内）；OpenAI 兼容服务不返回缓存字段时优雅降级，不影响对话与工具调用
- **N3 风格**：中文注释、中文文案，与既有代码约定一致
- **N4 可测试**：系统提示拼装与补充块生成是纯逻辑，可脱离网络与 TUI 独立单测（注入任意环境信息与开关状态，断言输出文本）
- **N5 缓存安全**：缓存断点只出现在稳定前缀上；动态补充内容永不携带缓存断点，防止动态内容被按轮次缓存
- **N6 兼容**：除 F4 的 Plan 注入迁移外，既有功能（TUI、工具执行、Agent Loop、错误处理）行为不变
- **N7 成本效率**：稳定前缀在会话内保持不变；连续多轮对话中缓存命中带来的输入 token 计费下降（由缓存命中字段可观测）

## 不做的事

- ❌ 项目指令文件加载（MEWCODE.md 从项目目录读取注入）——留待后续章节
- ❌ 自动记忆与长期记忆内容生成——本章只留「长期记忆」空槽位，无数据源
- ❌ 真实 MCP 接入与 Skill 系统——「已激活的 Skill」空槽位同理
- ❌ 自动化评估（脚本对比新旧系统提示的模型输出质量）——本章验证手段是缓存字段解析＋典型场景人工对比
- ❌ 上下文压缩 / 窗口管理——仍假定 30 轮迭代内不爆上下文
- ❌ OpenAI 协议下显式控制缓存断点——依赖服务端自动前缀缓存，不做协议外参数
- ❌ 上下文管理、会话持久化等其他章节规划的功能

## 验收标准

- **AC1（F1）**：构建出的系统提示文本包含七个固定模块，顺序为身份→系统约束→任务模式→动作执行→工具使用→语气风格→文本输出，后接环境信息；config 填写自定义指令时该模块出现、不填时不出现；三行原文语义完整体现（验证：单测断言模块顺序与关键句子）
- **AC2（F2）**：Anthropic 请求体中稳定系统块末尾与最后一个工具带缓存断点；OpenAI 请求体中系统消息的稳定文本在最前（验证：mock 请求体断言字段位置）
- **AC3（F3）**：动态补充块带特殊标签、位于缓存断点之后；会话历史中不出现补充块内容（验证：跑一轮循环后检查会话消息）
- **AC4（F4）**：Plan 模式第 1 轮注入完整指令、第 2-3 轮精简、第 4 轮完整（周期重复）；会话历史不再出现 PLAN_MODE_ON/OFF 消息；`/plan` 后请求体 tools 仍只含只读工具、`/do` 恢复全工具（验证：mock 多轮流断言每轮注入内容）
- **AC5（F5）**：工具使用/动作执行模块与 read_file、编辑类、shell、搜索类工具描述中均含「优先用专用工具」「编辑前必先读」的呼应表述（验证：文本检查）
- **AC6（F6）**：mock 流携带缓存字段时正确解析进用量信息、TUI 用量行展示缓存命中；不携带时不展示、行为不变（验证：单测＋TUI 观察）
- **AC7（F7）**：config.yaml 填写 custom_instructions 后系统提示中出现该内容；不填时正常启动、无该模块（验证：配置校验与拼装输出）
- **AC8（回归）**：全部既有单元测试通过；tmux 端到端正常对话（多轮、工具调用、Plan Mode 流程）
- **AC9（定性评估）**：提供一份典型场景清单（如多轮编辑同一文件、跨轮读文件再修改、Plan 调研、混合只读/写操作），供人工对比——观察模型行为质量与 TUI 缓存命中显示，作为定性评估依据（验证：按清单逐场景走查）
