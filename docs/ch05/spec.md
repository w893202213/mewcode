# Agent Loop Spec

## 背景

ch04 工具系统齐了，但模型每轮对话最多执行一个工具就停下，等用户再催下一句——多步任务（读文件→分析→改代码→跑测试）需要用户当「人肉循环」。本章给 MewCode 装上 Agent Loop：ReAct 模式（思考→调工具→看结果→再思考）多轮自动推进，直到任务完成或触发停止条件，让 MewCode 从被动应答变成能自主干活的 Agent。同时补上三块基础设施：异步事件流（Agent 与界面解耦）、多工具调用分批执行（只读并发、副作用串行）、Plan Mode 两段式（/plan 调研出计划，/do 切回执行）。

## 目标

- **ReAct 自主循环**：一轮轮调 LLM、执行工具、结果回灌，直到模型不再请求工具
- **完备停止条件**：模型说完、迭代上限、用户取消、连续未知工具、流出错，五种情况都能安全停下；迭代上限是兜底安全网
- **异步事件流**：Agent 只发事件（文本、工具调用、工具结果、Token 用量、进度），界面订阅渲染，彻底解耦
- **流式双路收集**：一边实时把文本推给界面，一边攒出完整响应供落盘与后续判断
- **分批执行**：单响应多工具调用时，只读工具并发跑、副作用工具按序串行跑
- **Plan Mode 两段式**：/plan 只放开读类工具让模型先出计划，/do 再切回全工具执行

## 功能需求

- **F1（Agent Loop）**：每轮把会话历史+工具列表发给 LLM；模型响应含工具调用时，执行该轮全部工具并把结果回灌进会话，自动发起下一轮；直到模型响应不再含工具调用，本轮结束。所有中间步骤（每轮 assistant 文本、工具调用、工具结果）都留在会话历史。
- **F2（停止条件）**：五种停止条件——① 模型不再调工具→正常结束；② 达到迭代上限（30 轮）→停止，提示已达上限；③ 用户取消（Ctrl+C）→停止，已完成步骤保留在会话中，提示已取消；④ 连续 2 次调用未知工具→停止，提示错误原因；⑤ 流出错（ProviderError）→停止，显示错误面板，本轮回滚（与 ch04 一致）。
- **F3（异步事件流）**：Agent 以事件流形式产出五类事件——文本增量、工具调用、工具结果、Token 用量、进度（第 N 轮）。界面只订阅事件渲染，Agent 内部不感知界面。实现：Agent 内部 asyncio 事件循环跑在后台线程，TUI 主线程经线程安全队列消费事件，保持同步渲染。
- **F4（流式双路收集）**：流式期间文本增量实时推给界面，同时拼接出完整响应文本；响应结束后完整文本落盘会话（含中间轮次的文本，模型后续能看到自己说过什么）。
- **F5（多工具分批执行）**：单次响应含多个工具调用时，先并发执行只读工具（读文件/找文件/搜代码），再按模型给出的顺序串行执行有副作用的工具（写文件/改文件/执行命令）；每个结果都回灌。
- **F6（循环中命令直接执行）**：Agent Loop 期间命令工具不弹 y/n 确认直接执行；命令工具的「需确认」标记保留，留给后续安全章节接管。
- **F7（Plan Mode 两段式）**：`/plan` 进入计划模式——工具列表收窄为只读工具，并注入提示让模型先调研、输出计划、不要动文件或执行命令；计划作为回复输出，本轮结束，模式保持不自动退出。`/do` 切回全工具模式，模型继续执行计划。
- **F8（Token 用量）**：每次 LLM 调用的输入/输出 token 数被解析出来，随事件流发给界面；一轮回复结束后 TUI 展示累计用量。
- **F9（TUI 展示）**：多轮循环中逐一展示每轮的工具调用（工具名+参数）与结果，显示「第 N 轮」进度；最终回复正常流式渲染；既有的双击 Ctrl+C 退出、/exit /clear /help、错误面板不受影响。

## 非功能需求

- **N1**：迭代上限固定 30 轮（代码常量），作为兜底安全网；达到后停止并明确提示。
- **N2**：停止条件触发后事件流干净收尾——发一个明确的结束事件（含停止原因），不再产出其他事件；界面收到结束事件后回到输入行。
- **N3**：不新增第三方依赖——asyncio、queue、threading 均为标准库。
- **N4**：所有错误与提示信息一律中文、可读、可操作（与现有约定一致）。
- **N5**：单工具语义不变——并发/串行执行不改变每个工具原有的超时（30 秒）、异常转错误结果、30000 字符截断行为。
- **N6**：Agent 核心逻辑可脱离 TUI 与线程测试——单元测试直接消费事件流断言行为（mock provider 即可，不启动界面）。
- **N7**：工具执行顺序稳定——并发批内部完成顺序不定，但结果回灌会话时按模型给出的原始顺序排列（模型看到的工具结果顺序与其调用顺序一致）。

## 不做的事

- 不做权限系统、命令白名单、危险命令检测（后续章节；本章循环中命令直接执行）
- 不做上下文压缩 / 窗口管理（迭代上限 30 轮内假定不爆上下文）
- 不做循环期间的用户交互式确认（y/n 机制保留在代码中，留给后续安全章节）
- 不做计划自动批准 / 自动进入执行（计划产出后必须用户输入 /do 才切回执行）
- 不做工具调用策略优化（记忆、子 Agent、多 Agent 编排、工具选择策略）
- 不做事件流持久化（事件仅存在于进程内存，退出即丢弃，与现有会话行为一致）
- 不做流式期间的部分响应重试（ProviderError 直接结束本轮，不自动重试）

## 验收标准

- **AC1（F1）**：mock LLM 模拟「读文件→改文件→执行测试」多步任务，Agent 自动多轮推进直至模型不再调工具；每轮请求体都包含之前轮次的工具调用与结果（两家协议各验证一次）。
- **AC2（F2）**：五种停止条件各触发一次——① 正常结束；② 迭代上限（mock 持续调工具，第 30 轮后停止并提示上限）；③ 取消（循环中 Ctrl+C 停止，历史保留已完成步骤，提示已取消）；④ 连续 2 次未知工具后停止并提示原因；⑤ 流出错显示错误面板并回滚本轮。
- **AC3（F3）**：无界面环境下（单元测试直接消费事件流）跑完一轮，断言五类事件齐全且顺序合理；TUI 中事件被渲染而非被丢弃。
- **AC4（F4）**：流式期间文本逐片可见；本轮结束后会话中落盘的最终回复与流式输出一致且完整。
- **AC5（F5）**：单响应含「读文件+搜代码+执行命令」时，两个只读工具并发执行、命令工具在其后串行执行；会话中工具结果的顺序与模型调用顺序一致。
- **AC6（F6）**：循环中模型调用命令工具时，不出现 y/n 提示，命令直接执行。
- **AC7（F7）**：/plan 后模型发起的请求体 tools 字段只含三个只读工具；模型输出计划文本后本轮结束、模式保持；/do 后请求体恢复六个工具。
- **AC8（F8）**：回复结束后 TUI 显示累计输入/输出 token 用量（mock 返回 usage 时能正确显示）。
- **AC9（F9）**：多轮循环时 TUI 显示「第 N 轮」进度，每轮工具调用与结果逐一可见；既有交互（双击退出、/help、错误面板）不受影响。
