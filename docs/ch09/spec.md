# 上下文管理 Spec

## 背景

ch01–ch08 之后，MewCode 有多轮 Agent Loop 和工具系统，但对话历史**只增不减**：工具结果单条可长达 30000 字符，多轮累积后必然逼近模型上下文窗口上限，请求报错、会话瘫痪。本章实现上下文管理能力：靠两层压缩策略——轻量预防 + 重量兜底——让 MewCode 在有限的 Token 预算里长时间干活。

## 目标

- Token 大头是工具结果，压缩从这里下手：超阈值存盘，对话里只留预览和文件路径
- 整体历史逼近窗口上限时，调 LLM 生成结构化摘要兜底，保住可用性
- 用户的原始消息尽量原文保留，不被摘要改写
- 用户可手动触发压缩；摘要连续失败 3 次熔断，避免死循环
- 不做精确 tokenizer：锚定 API usage、增量按字符近似估算

## 功能需求

### F1: 窗口上限配置化

- provider 配置新增可选字段 `context_window`（token 数），缺省 200000
- 非法值（非正整数）启动时抛 `ConfigError`，中文消息，fail-closed 口径与现有配置一致

### F2: Token 近似估算

- **锚点**：最近一次成功 API 请求的 `input_tokens`（usage）+ 该次请求发送的消息快照，作为基线
- **增量**：基线之后新增的消息按 `字符数 / 4` 估算 token；基线消息用锚点值，不重估
- 无锚点时（尚无成功请求）：全部消息按字符估算
- 估算口径 = 会话消息 + 系统提示（stable + dynamic），不含工具定义

### F3: 轻量预防（每次 API 请求前执行）

- **单条超阈值**：单个工具结果超过阈值（默认 12000 字符）时，完整内容写入磁盘文件；消息里替换为「预览（前 1000 字符）+ 文件路径 + 需要详情请读取文件」的提示
- **合计超阈值**：单条消息内多个工具结果合计超过阈值时，按内容从大到小依次存盘替换，直到合计低于阈值
- 用户消息不参与轻量压缩；已替换过的结果不重复处理（幂等）
- 存盘失败（磁盘满/无权限）降级：结果保持原文照常回灌，不阻断请求

### F4: 重量兜底（自动触发）

- **触发**：每次 API 请求前估算总量 ≥ 窗口上限 − 13000 时触发
- **保留区**：从尾部按估算 token 往回数约 10000 token，且至少 5 条消息；保留区原文不动
- **摘要区**（保留区之前的消息）：用户消息**一律原文保留**；assistant 回复与工具结果压缩进结构化摘要
- **摘要生成**：复用当前 provider，**不传任何工具**；Prompt 明确要求：禁止调工具、先写分析草稿（不进入正式摘要、用后即弃）再写正式摘要
- **摘要固定 6 部分**：总体目标与状态 / 已完成工作 / 关键文件与代码 / 重要事实与决策 / 未完成事项 / 注意事项
- **压缩后历史** = 摘要消息 + 边界消息 + 保留区原文；边界消息提示模型：以上是压缩摘要而非原文，涉及文件/代码细节请重新读取文件，不要照摘要直接修改代码

### F5: 手动触发（/compact）

- 输入 `/compact` 立即执行一次重量兜底压缩（无条件执行）
- 手动触发时安全余量收窄到 3000：压缩后估算总量 ≤ 窗口上限 − 3000（用户主动要压，可更贴近上限）

### F6: 摘要熔断

- 摘要 LLM 调用失败计数 +1，**连续 3 次失败熔断**：自动压缩不再发起，本次放弃压缩、按未压缩状态继续请求，并提示用户
- 成功压缩一次即重置计数；手动 `/compact` 总是允许发起，成功即解除熔断

### F7: 压缩可见性

- 压缩全程对用户可见：TUI 显示压缩开始/完成提示，含被压缩的消息条数、估算节省的 token 数；失败与熔断也给出中文提示

## 非功能需求

- **N1: 用户消息原文不改写**——轻量预防不触碰用户消息；重量摘要区中用户消息原样保留
- **N2: 压缩成本可控**——轻量预防零 LLM 成本；重量兜底每次压缩至多一次 LLM 调用；token 估算全程无网络请求
- **N3: 熔断防死循环**——摘要连续失败 3 次后自动压缩不再发起，压缩路径不会陷入「失败→重试→失败」循环
- **N4: 幂等**——轻量预防重复执行不产生重复存盘或内容变化；已压缩的历史再次估算不会对同一范围重复摘要
- **N5: 草稿隔离**——摘要的分析草稿不进入会话历史、不发给后续任何请求
- **N6: 降级不阻断**——存盘失败、估算异常等压缩路径错误一律降级，不阻断正常的 API 请求

## 不做的事

- 精确 tokenizer（tiktoken 等）：本章一律近似估算
- 摘要策略的机器学习优化（重要性评分、上下文选择模型等）
- 会话持久化：会话仍仅存内存、退出即丢；存盘的只是被压缩的工具结果文件
- 摘要的摘要（多级合并）：每次压缩只对原文区做一次摘要
- thinking 块的单独保留策略：assistant 消息的 thinking 内容随消息一起被摘要掉
- 工具定义的 token 优化（工具列表精简、按需加载）

## 验收标准

- **AC1**（F1）：配置不含 `context_window` 时按 200000 参与计算；含非法值时启动抛中文 `ConfigError`（验证：单测 + 启动观察）
- **AC2**（F2）：有 usage 锚点时估算 = 锚点值 + 增量消息字符数÷4；无锚点时全量字符估算（验证：单测）
- **AC3**（F3）：单条工具结果超阈值时，磁盘存在完整内容文件，会话消息仅含预览 + 文件路径 + 重新读取提示（验证：单测）
- **AC4**（F3）：单条消息内多结果合计超阈值时，按内容从大到小依次存盘，直到合计低于阈值（验证：单测）
- **AC5**（F4）：估算总量 ≥ 窗口−13K 时自动压缩；压缩后历史 = 摘要消息 + 边界消息 + 保留区原文；摘要含 6 个固定部分；摘要区用户消息原文保留；保留区 ≥ 5 条且 ≈10K token（验证：单测 + e2e）
- **AC6**（F4）：摘要 LLM 请求不带任何工具（验证：单测，mock provider 收到空工具列表）
- **AC7**（F5）：`/compact` 无条件执行压缩，压缩后估算总量 ≤ 窗口−3K（验证：e2e）
- **AC8**（F6）：摘要连续失败 3 次后自动压缩不再发起；成功压缩一次即重置（验证：单测）
- **AC9**（F7）：TUI 显示压缩开始/完成提示，含压缩条数与估算节省 token（验证：e2e 观察）
