# ch13 技能系统（Skill）Spec

## 背景

现状（ch12 后）：可复用的 AI 操作没有正式封装——`/review` 只是硬编码在 builtins.py 里的一段提示词；「提交代码」「跑测试修失败」这类固定流程，用户每次都要重新输入整段提示词。斜杠命令是静态内置的，用户不能自建；命令提示词不支持参数、不支持工具收窄、也没有独立执行能力。

## 目标

把可复用的 AI 操作封装成带元信息的 Markdown 文件（Skill），让用户输入一个短命令就能触发整套流程：

1. **三级存放**：项目 > 用户 > 内置，同名覆盖，坏文件跳过不阻断
2. **两阶段加载**：启动时只注入名字+一句说明（省 token），模型判断需要时经内置工具加载完整指令
3. **激活钉住**：加载后的完整指令钉在环境上下文最显眼位置，每轮重建，多技能可同时激活
4. **两种执行模式**：共享（结果留主历史）/ 独立（开独立对话跑完摘要回流）
5. **工具白名单**：收窄当前可用工具，提升模型选对工具的准确率
6. **斜杠短命令**：加载后自动注册，/clear 时一并清掉

## 功能需求

### F1 技能定义格式

- 单文件技能：一个 Markdown 文件，YAML frontmatter + 正文。frontmatter 字段：
  - `name`（必填）：唯一名字，非空、不含空白（要能作为斜杠命令名）
  - `description`（必填）：一句话说明（注入启动上下文）
  - `tools`（可选）：可见工具白名单（字符串列表）；缺省 = 不收窄
  - `mode`（可选）：`shared` / `independent`，缺省 `shared`
  - `history`（可选）：独立模式带入主对话最近消息条数（非负整数，缺省 0）
  - `model`（可选）：指定模型名（仅独立模式生效）
  - 未知字段忽略（向前兼容）；字段类型不对 = 解析失败
- 正文：发给模型的 SOP 指令，支持 `$ARGS` / `$ARGUMENTS` 占位符，激活时替换为用户传入内容；未传参数时替换为空串
- 目录型技能：一个目录，入口 Markdown（`SKILL.md`，格式同上）+ 模板/示例/辅助脚本/参考文档等资源文件，整套作为一个能力包分发；激活时技能目录路径一并注入，SOP 可用相对路径引用资源
- 解析失败的单个文件跳过（打印警告，不阻断整体）

### F2 三级存放与优先级

- 三级目录：项目 `.mewcode/skills/` ＞ 用户 `~/.mewcode/skills/` ＞ 内置（包内 `mewcode/skills/`）
- 同名技能按优先级覆盖：项目 ＞ 用户 ＞ 内置（静默覆盖）
- 同一级内重名：警告 + 按文件名排序后者跳过
- 内置三个样板：`commit`、`review`、`test`

### F3 两阶段加载

- 启动：扫描三级目录得到生效技能集，把每个技能的「名字 + 一句说明」注入对话上下文
- 使用：内置系统级工具 `use_skill(name, args)` 按名加载完整指令

### F4 激活与上下文钉住

- 激活：完整指令（参数替换后）钉在环境上下文最显眼位置（补充块之后、记忆/自定义指令之前），**每轮重建都在**
- 多个技能可同时激活，激活集合是会话状态
- 重复激活同一技能：幂等——从磁盘重读内容替换（**热更新**：编辑文件后再次加载即生效）
- 激活期间会话新增技能文件：不自动发现（重启生效）

### F5 工具白名单

- 激活技能的 whitelist 收窄当前可用工具：可见 = 各激活技能白名单**并集** + 系统级 `use_skill`；无激活技能时全部可见；计划模式的只读过滤照常叠加
- 执行侧兜底：白名单激活期间，模型调用白名单外工具 → 回灌失败结果「技能白名单未包含该工具」
- 启动校验：所有生效技能的 `tools` 字段若含不存在的工具名 → 启动立即报错退出（不静默降级）
- `use_skill` 是系统级工具：不受白名单约束，计划模式下也可见

### F6 两种执行模式

- `shared`（共享）：技能在当前对话执行——SOP 钉入上下文后，结果留在主历史
- `independent`（独立）：开独立对话执行——新鲜会话 + 主对话最近 N 条历史（frontmatter `history`）+ SOP 钉入独立上下文 + 用户参数作为任务；跑完最终回复作为**摘要回流**主历史；`model` 字段指定模型时独立对话用该模型
- 独立执行过程对用户可见（流式渲染、权限询问走主循环正常流程弹给用户）
- 独立对话不落会话存档（只有摘要进主历史）

### F7 斜杠短命令

- 技能加载（激活）后自动注册为斜杠短命令 `/<name>`，出现在 `/help` 与 Tab 补全
- 与内置命令撞名 → 该技能命令跳过注册并警告（内置命令优先）
- 执行：`shared` 模式 = SOP（参数替换后）作为用户消息注入主对话触发一轮；`independent` 模式 = 触发独立执行 + 摘要回流
- `/clear` 清空对话时顺带清掉已激活技能与已注册的技能命令

### F8 独立执行流程与摘要回流

- 触发途径一：模型经 `use_skill` 激活独立技能 → 工具返回「本轮结束后执行」→ 本轮结束后由主循环执行独立对话
- 触发途径二：用户输入 `/<name>`（已加载后）
- 独立对话跑完，最终助手回复作为摘要（带技能名标记）写回主历史并向用户展示
- 摘要回流后**自动触发主对话一轮**，模型基于摘要继续或向用户汇报

### F9 迁移 /review

- ch12 的 `/review` 内置命令删除，由内置 `review` 技能取代（行为等价：审查当前项目改动）
- 其余 11 条内置命令不变

## 非功能需求

- **N1 行为确定性**：技能扫描/解析/白名单校验全部纯本地计算，不消耗模型调用；坏文件跳过不影响启动
- **N2 可扩展**：新增一个技能 = 放一个 Markdown 文件，启动扫描即生效；加载后注册的命令自动进 `/help` 与 Tab 补全，无其他改动点
- **N3 解耦**：技能管理逻辑（扫描/解析/激活/白名单计算）不依赖渲染框架，可脱离 TUI 独立单测
- **N4 兼容**：ch12 除 `/review`（迁移给技能）外的 11 条命令行为不回退；ch09/ch11 验收场景不回退
- **N5 缓存友好**：技能名+说明注入稳定区（会话内不变，进缓存前缀）；激活指令在动态区（每轮重建，紧跟缓存断点）
- **N6 失败安全**：白名单引用不存在的工具启动即报错退出，不静默降级

## 不做的事

- 技能市场分发与版本管理（本章明确不做）
- 技能依赖声明/安装——目录型技能的资源文件只是文件，不处理导入安装
- 文件监听自动重载——热更新 = 下次加载时重读磁盘
- 技能反激活工具——`/clear` 是唯一出口
- `model` 字段在 shared 模式下生效——仅 independent 模式
- 技能之间的相互调用/组合
- 会话存档中保存独立对话——只有摘要进主历史

## 验收标准

- **AC1（F1）**：技能文件 frontmatter 缺 `name`/`description` 或字段类型不对 → 跳过该文件并打印警告，其余技能正常生效
- **AC2（F1）**：SOP 含 `$ARGS` 占位符 → 加载时替换为用户传入内容；未传参数 → 替换为空串
- **AC3（F2）**：项目/用户/内置三级放同名技能 → 项目级生效；用户级覆盖内置；同一级内重名 → 警告且后者跳过
- **AC4（F3）**：启动后上下文包含全部生效技能的「名字 + 一句说明」；被覆盖/解析失败的技能不出现在列表中
- **AC5（F4）**：激活技能后，完整 SOP（参数替换后）出现在环境上下文补充块之后的显眼位置；再激活第二个技能两者同时在；`/clear` 后全部清空
- **AC6（F4）**：激活技能后编辑其 Markdown 文件，再次激活 → 新内容生效（热更新）
- **AC7（F5）**：激活带白名单的技能后，模型收到的工具列表 = 白名单 ∪ {`use_skill`}；同时激活两个技能 → 白名单取并集
- **AC8（F5）**：白名单写不存在的工具名 → 启动报错退出（stderr 指出技能名与工具名）
- **AC9（F5）**：白名单激活期间模型调用白名单外工具 → 回灌失败结果「技能白名单未包含该工具」
- **AC10（F6 shared）**：shared 技能执行结果留在主历史，模型下一轮可见
- **AC11（F6 independent）**：独立技能跑完后最终回复作为摘要回流主历史并自动触发主对话一轮；`history: N` 时独立对话包含主对话最近 N 条消息
- **AC12（F7）**：技能加载后 `/<name>` 出现在 `/help` 与 Tab 补全中；`/clear` 后命令消失
- **AC13（F7）**：技能名与内置命令撞名 → 加载后该技能命令跳过注册并警告，内置命令行为不变
- **AC14（F9/N4）**：`/review` 迁移为 review 技能后行为等价；其余 11 条内置命令按 ch12 验收场景重跑不回退
