# 五层防御权限系统 Spec

## 背景

ch01–ch06 之后 MewCode 能对话、用六个工具干活、跑多轮 Agent Loop，但安全上处于裸奔状态——ch05 明确「命令直接执行，确认机制留给后续安全章节」：`run_command` 以 `shell=True` 执行任意命令，`write_file`/`edit_file` 可写任意路径（含项目外与符号链接逃逸），模型一次越界调用没有任何拦截层；`requires_confirmation` 标记闲置在 Tool 基类里。本章把权限系统装进 Agent Loop 的执行入口。

## 目标

- 五层防御分层协作：黑名单硬拦 → 路径沙箱 → 可配置规则 → 权限模式兜底 → 人在回路最终确认
- 权限拒绝不终止 Agent Loop：拒绝结果回灌给模型，让它调整策略继续
- 规则可声明、可持久化：用户级/项目级/本地级三个 YAML 合并生效

## 功能需求

### F1: 黑名单硬拦截

- 执行前用正则检查 `run_command` 的 command 参数；命中内置高危模式（`rm -rf /`、`mkfs*`、`dd`、fork bomb、`sudo`、`curl|sh` 等）即拒绝执行，回灌含命中原因的中文失败结果，循环继续
- 内置黑名单**不可被配置、规则、模式放开**，放行档下同样生效

### F2: 路径沙箱

- 五个文件工具（read_file/write_file/edit_file/find_files/grep_code）的路径参数一律限定在项目根（启动目录）内
- 判定前先解析符号链接（含中间路径组件），再做前缀判断防逃逸；目标不存在时按解析后的父路径判断
- 越界即拒绝并回灌失败结果；**硬边界**，规则与模式均开不了例外
- run_command 不受路径沙箱约束（shell 可任意 cd），由黑名单+规则+询问覆盖

### F3: 可配置规则

- 规则形式「工具名(模式)」，如 `run_command(git *)` 放行所有 git 命令；模式支持精确与 glob（`*`/`**`/`?`）
- 匹配对象：run_command → command 参数；五个文件工具 → file_path 参数
- 裁决三种：allow / ask / deny。YAML 存储，示例：

  ```yaml
  rules:
    - tool: run_command
      pattern: "git *"
      action: allow
    - tool: read_file
      pattern: "**/*.env"
      action: deny
  ```

- 三个文件：用户级 `~/.mewcode/permissions.yaml`、项目级 `<项目根>/.mewcode/permissions.yaml`、本地级 `<项目根>/.mewcode/permissions.local.yaml`；启动时合并读取，**层级只决定写入位置**
- 文件缺失跳过；文件损坏启动时报配置错误（fail-closed：宁可不启动，也不带着可能缺失的 deny 规则跑）

### F4: 多档权限模式

- 三档：strict / default / accept。**规则优先，模式只填未命中**：
  - default：未命中 → 只读工具放行、副作用工具询问
  - strict：未命中 → 只读工具放行、副作用工具拒绝
  - accept：未命中 → 一律放行（deny 规则、黑名单、沙箱仍生效；ask 规则仍询问）
- `/mode` 命令循环切换三档，本会话生效；config.yaml 可选字段 `permission_mode` 决定启动档位（缺省 default，非法值报配置错误）；切换与欢迎语显示当前档位

### F5: 人在回路

- 裁决为 ask 时暂停该次调用，展示工具名+参数摘要与四个选项：**本次允许 / 本会话允许 / 永久允许 / 拒绝**
- 本次允许：仅放行该次调用
- 本会话允许：内存登记该「工具+模式」的 allow 规则，会话内生效、退出即弃
- 永久允许：该 allow 规则写入**本地级** YAML，立即生效
- 拒绝：回灌失败结果，循环继续
- 询问期间按 Ctrl+C → 取消本轮（与既有取消语义一致）

### F6: 规则合并优先级

- 三个文件合并为一个规则集合；命中多条时按结果类型裁决：**deny > ask > allow**，与规则所在层级无关
- 模式只填未命中部分，不覆盖任何已命中规则的裁决

### F7: 拒绝不终止循环 + 裁决顺序

- 任何一层拒绝（黑名单/沙箱/deny 规则/严格档/用户拒绝）都产出失败 ToolResult 回灌，Agent Loop 继续，模型可调整策略
- 全量裁决顺序：计划模式拦截（沿用 ch05）→ 黑名单 → 沙箱 → 规则合并 → 模式兜底 → 询问；任一层拒绝即短路

## 非功能需求

- **N1 依赖**：不新增第三方依赖——正则、glob（fnmatch）、路径解析（pathlib）全部标准库实现
- **N2 性能**：裁决在工具执行前内存中完成，单次调用开销可忽略；询问期间等待在后台线程，TUI 渲染不挂起
- **N3 风格**：中文注释、中文文案，与既有代码约定一致
- **N4 行为变更说明**：默认档下副作用工具（run_command/write_file/edit_file）从 ch05「直接执行」改为「默认询问」——这是本章的**有意变更**，ch05 checklist 场景 5 相应更新；读类工具行为不变
- **N5 拒绝消息可操作**：每层拒绝的消息都含明确原因与可执行的提示（如「路径越界: 仅限项目目录内」「命中黑名单模式」），让模型能据此调整策略而非盲目重试

## 不做的事（留给后续章节）

- 网络请求限制（阻止外联）
- 资源配额（CPU/内存/磁盘/超时配额管理）
- 审计日志（权限决策留痕）
- 规则的可视化管理命令（如列出/编辑规则集的 /permissions）
- 多项目根（沙箱只认启动目录一个根）
- 黑名单自定义扩展（内置固定列表）
- 询问超时自动拒绝（询问无限等待，用户 Ctrl+C 取消）

## 验收标准

- **AC1（F1）**：向 Agent 发送会调用 `run_command` 且命令命中黑名单（如 `rm -rf /`）的请求 → 命令不执行，工具结果面板显示含「黑名单」的失败原因，Agent Loop 继续且模型能给出调整后的回应
- **AC2（F2）**：调用 `write_file`/`read_file` 写/读项目外路径（`../` 上级、绝对路径、指向项目外的符号链接）→ 一律拒绝并显示越界原因；项目内路径（含项目内符号链接）正常执行
- **AC3（F3）**：三个 YAML 按层级合并读取；`run_command(git *)` 精确/glob 匹配行为正确；损坏的规则文件启动时报配置错误
- **AC4（F4）**：`/mode` 三档切换后未命中行为符合各档定义；config.yaml 设 `permission_mode: strict` 启动即严格档；非法值报配置错误
- **AC5（F5）**：ask 裁决暂停执行并展示选项；「本次允许」仅放行一次、「本会话允许」会话内不再询问、「永久允许」写入本地级 YAML 且重启后仍生效、「拒绝」回灌失败结果
- **AC6（F6）**：用户级 allow + 项目级 deny + 本地级 ask 三条规则同时命中 → 最终 deny；去掉 deny 后 → ask
- **AC7（F7）**：黑名单/沙箱/规则/严格档/用户拒绝五种拒绝路径下 Agent Loop 均不终止，模型收到失败结果后可继续调工具或给出回复
